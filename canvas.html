Glossary

How to read the feature canvas. A node is one box; a room groups them; the rest describes what a node is and how complete it is.

Structure

Node
One box on the map — a single thing you can click (a feature, page, service, table…).
Room
A group / swimlane: a domain or area of the app (Auth, Trading). Holds many nodes. Organization only — a room has no spec of its own.
Feature
A node that's a unit of capability or work, usually backed by a spec. Lives inside a room. (One room → many features.)
Layer
What a node is architecturally — shown by its border color. Frontend / Backend / Data / External (see Kinds).
Depends-on / edge
What a node needs. Drawn as the arrows in the graph (a page → the service it calls → the table it reads).

Kinds & layers — the border color

page
Frontend. A screen with its own route (/login).
component
Frontend. A reusable UI piece with no route of its own (lives inside pages).
endpoint
Backend. A single API route (POST /api/…).
service
Backend. A logic module; usually owns several endpoints.
schema
Data. A table / data model.
integration
External. A third-party service.
feature
Vertical slice. A whole capability spanning layers — the default when you haven't decomposed it.

Status — the dot color

planned
Intended / spec'd, not built yet.
built
Exists in code; no verification yet.
in-progress
Partly verified, or actively being worked.
verified
All verification checkpoints pass.

Fidelity tiers — how much backs a node

Stub
On the map only (id / kind / room / depends-on). No spec, no code read. "It exists." (declared in _nodes.yml)
Cover
A code-derived verification snapshot of current behavior — checkpoints, no requirements/design. (/cover)
Spec
The full contract: requirements + design + tasks + verification. For pressing, actively-built work. (/spec)

A spec — its files

requirements.md
Problem, goals, non-goals, constraints (→ invariants).
design.md
Approach, affected components, API surface, failure modes, alternatives.
tasks.md
Ordered, PR-sized tasks (→ the board).
verification.md
Checkpoints that prove it works (spec-derived = a contract; code-derived = a snapshot).

In the detail panel

Checkpoints
Observable pass / fail / pending checks (CP-N) that prove the feature behaves.
Board
Done / Doing / Next — from tasks.md checkboxes ([x]/[~]/[ ]) plus free ## Doing / ## Next bullets.
Invariants
Rules that must not break (from requirements.md constraints).
Surfaces
The routes / endpoints / commands the node exposes.

Getting around

Tree vs Graph
The index (what exists, where) vs the dependency map (how it connects).
Group: Rooms / Layers
Group by domain, or by frontend / backend / data (the "flat by type" view).
Filters
Search, the room dropdown, and the kind chips.
Click / double-click
Click a node → highlight everything that depends on it. Double-click (or a dependency chip) → frame the node and its direct links.
